Save the current working context to a <problem_name/task_name>.WIP.md file. 

Focus on the current problem we're handling. Include as additional context important details from the conversation history, codebase exploration, debugging, work done, to save time when picking up this thread of work again - in particular - which commands to run to troubleshoot or test things. 

We might be coming back to this issue after a long period of time and may not remember most details - so be careful in nothing things down.

There's no need to gather additional context. Start by planning out the document structure. The WIP document is intended to be append only.
